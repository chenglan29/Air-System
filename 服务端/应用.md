# 应用
## V1
服务器应用储存在 software/ 下，规则如下：
系统会扫描指定文件夹下的 .js 文件，但是不会执行指定文件夹下的文件夹的 .js 文件，
并且 .js 的写法遵循 modules
例如:
```js
module.exports = (data,socket) => {
    socket.send(JSON.stringify({
        "type":"eval",
        "script":`alert("=)")`
    }));
}
```

具体语法见 index.js 的各个 batchScript();

下面是一些事件的列表:
+ software/closeConnection/ - 关闭连接时触发
+ software/createConnection/ - 有设备创建链接时触发
+ software/getMessage/ - 收到消息时触发（可发生在未登录时）
+ software/getMessage_doLogin/ - 收到消息时触发（仅发生在登录时）
+ software/initServer/ - 启动服务器时触发
+ software/login/ - 登录时触发
+ software/ptp/ - 与指定软件通讯
## V2
V2版本的API从1.12.7开始使用

您可以在software创建一个以应用名命名的文件夹

并创建一个文件 index.json ，内容格式如下
```js
{
    "name":"",//应用名
    "developer":"",//开发者信息
    "describe":"",//应用介绍
    "versionNumber":1,//应用版本号
    "versionName":"0.1",//应用版本名
    "dependentSoftwares":[],//依赖的其他软件或库
    "AvailableSystemVersions":[],//支持的系统版本
    "UnavailableSystemVersions":[],//不支持的版本
    "priority":0,//运行的优先级
    "event":{
        "closeConnection":[],//关闭链接时执行的 .js 文件路径，格式同V1
        "createConnection":[],//创建链接时执行的 .js 文件路径，格式同V1
        "getMessage":[],//收到信息时执行的 .js 文件路径，格式同V1
        "getMessage_doLogin":[],//登录后收到信息时执行的 .js 文件路径，格式同V1
        "initServer":[],//启动ws服务器时执行的 .js 文件路径，格式同V1
        "login":[],//登录时执行的 .js 文件路径，格式同V1
        "ptp":[]//与指定软件通讯时执行的 .js 文件路径，格式同V1
    }
}
```
具体语法见 index.js 的各个 appList.forEach(...)
